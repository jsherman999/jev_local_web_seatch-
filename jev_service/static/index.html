What Jev adds—and how an app uses it

Regular LLM: this demo asks a text model to generate a JSON action and any text to type. The app validates that output before using the browser.

Jev: the app supplies visible controls and allowed choices. Jev returns the operation and possible targets in one request. The app uses only the target for the chosen operation. A separate text LLM writes field values only when needed.

That can save time and cost on repeated decisions, while keeping actions within an explicit set. It still needs outcome checks and a text model for writing. The measurements here show this particular task, not a general ranking.

Your app → Jev service → browser → page text and source links → your app’s analysis. A backend submits a URL and goal to POST /v1/jobs, polls the returned job ID, and consumes the result. The model API itself can also power routing, classification, and other constrained decisions without a browser.

These diagrams expose our application code and observable API calls. They do not expose either provider’s model weights, hidden reasoning, or server implementation. Browser previews are for you; both policies read structured page text.
